# Журнал

Офлайн-застосунок (PWA) для швидкого запису службових подій: задач, несправностей, руху майна, пального, особового складу.

- **Дані ніколи не залишають пристрій.** Немає сервера, аналітики, CDN і зовнішніх шрифтів. Після завантаження застосунок не робить жодного мережевого запиту: це забезпечує `Content-Security-Policy` з `connect-src 'none'`.
- Працює повністю без мережі після першого відкриття.
- Дані зберігаються в IndexedDB браузера на цьому пристрої.

> ⚠️ **Не видаляйте іконку застосунку з початкового екрана без свіжого бекапу.** Разом з іконкою iOS видаляє всі дані застосунку.

---

## Встановлення

### iPhone (основна платформа)

1. Відкрийте адресу застосунку в **Safari**. Саме в Safari: Chrome та інші браузери на iPhone не вміють встановлювати PWA як окремий застосунок.
2. Натисніть **Поділитися** (квадрат зі стрілкою) → **На початковий екран** → **Додати**.
3. Далі запускайте застосунок **лише з іконки**. У Safari і в застосунку з початкового екрана окремі сховища: записи, зроблені в Safari, не з'являться в застосунку, і навпаки.
4. Відкрийте застосунок один раз за наявності мережі. Після цього він працює офлайн.
5. Перевірте **⚙ → Сховище → Постійне сховище**. Якщо там «не надано», натисніть «Попросити ще раз». На iOS постійне сховище зазвичай надається застосунку, встановленому на початковий екран.

### Android (Chrome / Samsung Internet)

1. Відкрийте адресу в Chrome або Samsung Internet.
2. Меню ⋮ → **«Додати на головний екран»** або **«Встановити застосунок»**.
3. Запускайте з іконки. Працює офлайн так само, як на iPhone.

### Windows (Chrome / Edge)

1. Відкрийте адресу в Chrome або Edge.
2. Натисніть іконку **«Встановити»** в адресному рядку (або меню ⋮ → «Встановити застосунок» / «Застосунки → Установити цей сайт як застосунок»).
3. Застосунок з'явиться в меню «Пуск» і працюватиме в окремому вікні.

### Mac

- **Safari (macOS 14+):** меню **Файл → Додати в Dock**.
- **Chrome:** іконка «Встановити» в адресному рядку.

На кожному пристрої дані свої: відкривши застосунок на іншому телефоні, ви побачите порожній журнал. Перенести записи можна через бекап («Експорт» на одному пристрої → «Імпорт → Злити за id» на іншому). Синхронізація файлом з'явиться на етапі 3.

## Бекап і відновлення

iOS може очистити дані веб-застосунку, якщо на телефоні мало місця або застосунком довго не користувались. **Бекап — єдиний захист від втрати даних.**

### Зробити бекап

1. **⚙ → Бекап → Експорт бекапу.**
2. На iPhone відкриється меню «Поділитися». Оберіть **«Зберегти у Файли»** (наприклад, «На iPhone») або AirDrop на свій ноутбук.
3. На комп'ютері файл `journal-РРРР-ММ-ДД_ГГХХ.journal-backup` просто завантажиться.

Файл містить усі записи, категорії, довідники та налаштування. На етапі 1 він **не зашифрований**, тож зберігайте його як службовий документ. Шифрування паролем з'явиться на етапі 3.

### Відновити з бекапу

1. **⚙ → Бекап → Імпорт бекапу** → оберіть файл.
2. Оберіть режим:
   - **Злити за id**: нові записи додаються, новіші версії замінюють старі, нічого не видаляється. Безпечно, можна повторювати.
   - **Замінити все**: усі поточні дані видаляються й замінюються даними з файлу (з підтвердженням).

Бекап зі старішої версії застосунку автоматично проходить міграції. Бекап з новішої версії не імпортується: спершу оновіть застосунок.

## Чекпоінти й нагадування

**Чекпоінт** — це короткий огляд кілька разів на день (за замовчуванням 09:00, 14:00, 21:00; змінюється в ⚙ → Чекпоінти). Коли ви відкриваєте застосунок після часу чекпоінту, одразу з'являється екран:

1. «Що сталося з останнього чекпоінту?» — кілька записів поспіль.
2. «Що нове висить?» — швидке додавання задач (Enter — додати).
3. Відкриті задачі з можливістю закрити. Увечері — ще й те, що має термін завтра.
4. «Готово».

Якщо пропустили кілька чекпоінтів, з'явиться лише один, найсвіжіший. Кнопка «Пізніше» закриває екран без позначки «пройдено».

Також при першому відкритті за день показується екран **«Сьогодні»**: прострочене, на сьогодні, вчорашні відкриті задачі, скільки було записів учора.

### Чому застосунок сам не надсилає сповіщення

Сповіщення за розкладом у вебзастосунку на iPhone можливі лише через сервер (Web Push), а сервера й мережі тут свідомо немає. Тому нагадування ставить сам телефон.

### Варіант 1 (рекомендовано): Календар

1. ⚙ → Чекпоінти → **«Додати чекпоінти в Календар»**.
2. На iPhone: «Поділитися» → **«Зберегти у Файли»** → відкрийте файл у «Файлах» → **«Додати всі»** в Календар.
3. У Календарі з'являться щоденні події з нагадуванням. Працює без мережі.
4. Тап по сповіщенню відкриває Календар — далі відкрийте Журнал з іконки.

Так само для окремої задачі з терміном: «Висить» → тап по задачі → **«У календар»**.

Якщо змінили час чекпоінтів — видаліть старі події в Календарі й додайте файл заново.

### Варіант 2: «Команди» → «Автоматизація»

1. Відкрийте **Команди** → вкладка **Автоматизація** → **«+»** → **«Час доби»**.
2. Вкажіть час (наприклад, 09:00), «Щодня», **«Запускати одразу»**.
3. Дія: **«Показати сповіщення»** з текстом «Журнал: чекпоінт».
4. Повторіть для 14:00 і 21:00.

Відкрити саме встановлений застосунок з «Команд» надійно не вийде (iOS відкриє Safari з окремим, порожнім сховищем), тому в сповіщенні лише нагадування — застосунок відкривайте іконкою.

## Категорії й довідники

- **⚙ → Категорії**: додати, перейменувати, емодзі, колір, група, порядок (тягніть ≡), архів, поля, «створює задачу». Категорію з записами можна лише архівувати — записи лишаються й показуються.
- **Поля**: текст, число (з одиницею), дата, вибір (варіанти через кому), людина / техніка / майно / місце (з автодоповненням). Перейменування поля не ламає старі записи.
- **Роль у підсумках**: пальне, виїзд, майно (отримано / видано / ремонт-списання), несправність. За нею «Вибірка» рахує числові підсумки.
- **⚙ → Довідники**: люди, техніка, майно, місця. Поповнюються автоматично з полів записів, редагуються вручну.

## Вибірка й експорт

Вкладка **«Вибірка»**: період (сьогодні, вчора, тиждень, місяць, довільний) і категорії. Записи згруповано за категоріями, хронологічно. Підсумки: пальне по авто й типу, кілометраж, майно, несправності й середній час до закриття.

- **«Копіювати текст»** — чистий текст для вставки у звіт.
- **.txt / .csv / .json** — файли (на iPhone через «Поділитися»). CSV з роздільником «;» відкривається в Excel.

## Синхронізація між пристроями

> З'явиться на етапі 3. Синхронізація йтиме зашифрованим файлом через AirDrop, кабель або флешку, без жодного сервера.

## Оновлення застосунку

Коли виходить нова версія, при наступному відкритті з мережею внизу з'явиться плашка **«Є оновлення» → «Оновити»**. Поки курсор стоїть у полі введення, плашка не показується. Незбережений текст лишається в чернетці.

## Розробка

Потрібен Node.js 22+.

```bash
npm install
npm run dev        # dev-сервер (без CSP і без service worker)
npm test           # юніт-тести (Vitest)
npm run build      # продакшн-збірка в dist/
npm run preview    # перегляд збірки на http://localhost:4173
npm run icons      # перегенерувати PNG-іконки (локально, без мережі)
```

### Структура

```
src/i18n/uk.ts      усі тексти інтерфейсу
src/db/             схема IndexedDB (Dexie), міграції, seed категорій, запис змін
src/domain/         чиста логіка: фільтри, задачі, час
src/io/             бекап, віддача файлів (Share Sheet / завантаження)
src/ui/             екрани й компоненти (Preact)
tests/              юніт-тести
```

### Правила для змін схеми

- Існуючі версії в `src/db/schema.ts → DB_VERSIONS` **ніколи не редагуються**: лише додається нова версія з `upgrade()`.
- Якщо змінюється форма даних, додається крок у `BACKUP_MIGRATIONS` (`src/io/backup.ts`).
- Кожна міграція має тест у `tests/migrations.test.ts`.
- Усі сутності мають `id`, `updatedAt`, `deviceId`, а видалення роблять лише через `deletedAt` (tombstone). Це потрібно для синхронізації.

### Деплой на GitHub Pages

Репозиторій може бути публічним: у ньому лише код. Файли бекапів і експорту внесено в `.gitignore`. **Ніколи не комітьте реальні дані.**

1. Створіть репозиторій на GitHub і запуште гілку `main`.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
3. Кожен push у `main` запускає `.github/workflows/deploy.yml`: тести → збірка з `BASE_PATH=/<назва-репозиторію>/` → публікація.
4. Адреса: `https://<користувач>.github.io/<назва-репозиторію>/`.

### Перевірка «без мережі»

1. `npm run build && npm run preview`, відкрити http://localhost:4173.
2. DevTools → Application → Service Workers: воркер активний.
3. DevTools → Network → **Offline**, перезавантажити сторінку: застосунок працює.
4. Після завантаження вкладка Network не показує жодних нових запитів під час роботи.
